# MemOS中间件及其能力

> 2026-10-02；提交 `a7367d07`。本文同时说明外部基础设施中间件与应用请求处理middleware，两者的部署/执行边界不同。依据源码实际挂载和调用，未启动服务验证运行栈。

## 1. 外部基础设施

| 中间件/服务 | 使用能力 | 进入哪些流程 | 启用与边界 |
|---|---|---|---|
| Redis | Streams consumer group、pending claim、ACK、Hash/Set状态、锁、TTL、历史窗口 | Scheduler任务、业务task→item映射、API混合检索、可选Redis ORM | MEMSCHEDULER_USE_REDIS_QUEUE等；不是正文向量数据库 |
| Redis Lua/GCRA | 原子model quota、TIME、理论到达时间 | OpenAI兼容LLM出站admission，QPS/burst/等待/重试 | 独立规则默认关闭；复用Scheduler连接配置 |
| Redis sorted set | 滑动窗口、计数/到期 | Krolik入站HTTP限流 | REDIS_URL独立；不可用回退进程内，非分布式同等保证 |
| RabbitMQ/Pika | exchange/queue、发布/消费、ACK、重连/暂存 | Scheduler Web/MemoryChange业务事件 | AuthConfig有配置才连接；不是Redis任务队列替代 |
| Neo4j/Community | 节点边/子图、租户过滤、原生或组合向量 | Tree记忆、Reader/Search/Feedback/Dream | Community组合VecDB；部分全文/图方法占位 |
| PolarDB AGE/Postgres pgvector | Cypher/SQL、JSONB、连接池、向量/部分全文 | 对应图后端和专有反馈/检索 | 扩展/schema需部署；不默认同时使用 |
| Qdrant/Milvus | collection、向量/payload、hybrid/过滤 | GeneralText/独立偏好/community组合 | API初始化未单独创建VecDB；部署Qdrant不代表请求必经 |
| MySQL/SQLite/SQLAlchemy | 事务/元数据/状态保存 | User/Cube、配置、Monitor | 不与记忆正文/认证库混为一份 |
| OSS | 文件对象上传/下载/链接 | 技能ZIP/SKILL文件，可选通知上传 | 配置和SDK齐全才生效；不是所有Memory必需 |
| Nacos | HTTP拉properties、写env、可选周期轮询 | APIConfig初始化与配置获取 | 缺地址/data-id/AK/SK跳过；watch不自动重建client |
| 模型/Embedding/BGE服务 | 推理、编码、相关性评分 | Reader/Memory/Search/Chat等 | 属provider外部依赖，非请求middleware |

证据：[Redis队列](../src/memos/mem_scheduler/task_schedule_modules/redis_queue.py)、[状态](../src/memos/mem_scheduler/utils/status_tracker.py)、[RabbitMQ](../src/memos/mem_scheduler/webservice_modules/rabbitmq_service.py)、[LLM限流](../src/memos/llms/rate_limit.py)、[API配置](../src/memos/api/config.py)。Node本地插件的SQLite、Hub和Provider是另一套独立基础设施。

## 2. Python请求处理中间件

### 2.1 两个入口的挂载不同

| 入口 | 源码显式安装 | 实际未安装的能力 |
|---|---|---|
| server_api:app | RequestContextMiddleware、StaticFiles、产品Router、异常handler、plugin init_app | 未注册全局API Key、CORS、RateLimit、SecurityHeaders |
| server_api_ext:app | CORS、SecurityHeaders、条件RateLimit；产品/admin Router | 没有基础RequestContextMiddleware和plugin init_app；没有全局产品API Key依赖 |

扩展app显式注册顺序是CORS→SecurityHeaders→RateLimit；按Starlette逆注册栈规则，请求通常先进入RateLimit→SecurityHeaders→CORS→Router。此顺序为源码和框架机制归纳，未实测。限流提前返回的429不会经过内部Security/CORS响应加工。

### 2.2 各能力与用途

| 组件 | 能力 | 作用/配置 | 边界 |
|---|---|---|---|
| RequestContextMiddleware | header trace或生成trace，API path/env/user/source | 请求日志、线程传播；基础app | 上下文字段不是认证/授权证明 |
| CORSMiddleware | origin/method/header/credentials | 扩展app CORS_ORIGINS | 浏览器跨域限制，不代替身份认证 |
| SecurityHeadersMiddleware | nosniff、Frame DENY、Referrer/Permissions等header | 下游返回后加工响应 | 不处理数据库或用户权限 |
| RateLimitMiddleware | Redis滑动窗口，内存回退，429/限流header | RATE_LIMIT_ENABLED默认true，100/60s；扩展入口 | 按key/IP，进程内回退受worker边界影响 |
| verify_api_key/require_scope | Authorization前缀、master/internal、Postgres hash/scopes | FastAPI Depends，admin密钥操作 | 不是全局BaseHTTPMiddleware；AUTH_ENABLED默认false |
| APIExceptionHandler | 请求校验/HTTP/ValueError/未知异常转JSON | app异常注册 | 流式已发送响应的错误另有生命周期限制 |
| StaticFiles | 下载/静态文件 | /download映射FILE_LOCAL_PATH | 目录存在性是启动前提 |
| 插件register_middleware | app.add_middleware扩展 | 安装/启用插件后init_app阶段 | 仓库无具体PluginMiddleware类；Dream用Hook/Router，未注册middleware |

证据：[基础app](../src/memos/api/server_api.py)、[扩展app](../src/memos/api/server_api_ext.py)、[request_context](../src/memos/api/middleware/request_context.py)、[auth](../src/memos/api/middleware/auth.py)、[rate_limit](../src/memos/api/middleware/rate_limit.py)。

重要行为：入站limiter只把原始Authorization以krlk_开头识别成key维度，Bearer/Token前缀可落到IP分支；认证函数则会去这些前缀。两者不应当成同一解析器。is_internal_request直接比较header与环境secret，两者都缺失时也会相等；源码没有非空检查，不能宣称始终要求非空内部密钥。

`AUTH_ENABLED=true`不会自动让`/product/*`执行verify_api_key；是否调用依赖由路由挂载决定。本文是实际行为记录，不将配置名字当功能已生效的证据。

## 3. Node本地服务

### 3.1 v2原生HTTP处理管道

```text
URL/旧agent prefix处理
→ 非/api的GET/HEAD静态文件
→ 若传ServerOptions.apiKey则API Key检查
→ 若home的.auth.json存在则Cookie会话检查
→ exact/pattern route匹配
→ body读取/大小限制
→ Handler/JSON或SSE响应
```

| 文件/组件 | 能力 | 运行边界 |
|---|---|---|
| server/middleware/auth.ts | Bearer/x-api-key，错误401 | options.apiKey有值才启用；当前Adapter/Bridge启动未传此值 |
| server/routes/auth.ts | scrypt密码、HMAC会话、7天Cookie、按agent隔离 | `.auth.json`存在才保护；auth/health与特定loopback规则豁免 |
| server/middleware/io.ts | body上限、JSON解析、响应 | 默认1MiB，import允许更大64MiB |
| server/middleware/static.ts | 路径解析/MIME、读取或stream | 非业务API；路径/资源校验 |
| server/http.ts | 路由、错误、旧prefix、生命周期 | 自实现原生node:http，非Express middleware |
| core/hub | team/user token与角色/状态 | 独立Hub认证边界，非Viewer Cookie |

证据：[http.ts](../apps/memos-local-plugin/server/http.ts)、[auth.ts](../apps/memos-local-plugin/server/routes/auth.ts)、[middleware](../apps/memos-local-plugin/server/middleware/)。auth中出现loopback `/api/v1/rpc`豁免规则，不等于registry实际注册了该URL；当前Bridge主协议是stdio JSON-RPC。

### 3.2 v1

Viewer先设置CORS、处理OPTIONS，公开auth/status/setup/login/reset与HTML；随后全部业务路由检查session。密码SHA256+固定salt，session存进程内Map，Cookie24小时、按端口名、HttpOnly/SameSite；与v2 scrypt/HMAC不同。重启Map会丢会话。

Hub info公开，join用teamToken，其他Bearer→签名/到期→用户active/tokenHash→按路由角色。Viewer Cookie不能作为Hub Bearer。证据：[Viewer](../apps/memos-local-openclaw/src/viewer/server.ts)、[Hub](../apps/memos-local-openclaw/src/hub/server.ts)、[Hub auth](../apps/memos-local-openclaw/src/hub/auth.ts)。

## 4. Cloud和Electron

| 系统 | 使用能力 | 边界 |
|---|---|---|
| Cloud配置UI | loopback、启动随机token、app.js token、API header token、self CSP | heartbeat和资源部分公开；UI token不是云MemOS API Key |
| OpenWork BrowserWindow | nodeIntegration=false、contextIsolation=true | Renderer通过preload暴露能力，不能直接把主进程Node API当浏览器API |
| preload/main IPC | 指定channel、错误规范化、部分sender/window检查 | task:start/resume有专门检查；不能称全部IPC同样鉴权 |
| IPC validation/Zod | 字符串/路径/工具/权限响应/URL检查 | 各channel规则不同 |
| 权限/问题HTTP | POST JSON校验→活动task/window→Renderer问题→等待/超时 | loopback9226/9227，未见API Key/Bearer检查 |
| dev-browser Express/Hono | HTTP页面管理、WebSocket/CDP、浏览器relay | 工具子项目，不能泛化整个Node主服务都用Express |

## 5. 与中间件相邻但不同的机制

ContextVar/日志Filter/计时decorator是横切工具；Plugin Hook是进程内部扩展；MCP/JSON-RPC是工具/桥接协议；provider client是出站调用；DB Manager是数据访问。它们都参与请求，但并非都属于同一HTTP middleware栈。

部署哪些外部服务见 [10-部署机制.md](10-部署机制.md)，配置生效路径见 [6-配置文件.md](6-配置文件.md)。本文不检查外部安装插件，也不添加假设性的统一鉴权保证。
